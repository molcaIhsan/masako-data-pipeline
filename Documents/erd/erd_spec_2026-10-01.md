## Legend (from the board)

```
LEGEND

Crow's foot: | = exactly one · o| = zero or one · o< = zero or many
Parent end = exactly one (zero-or-one when the FK is nullable/conditional). Child end = zero or many.
product_detail → product is 1:1.
One line per FK column: the child end starts at its FK row; the parent end lands on the parent's PK area.
Line colour = the parent (referenced) table's header colour.
Lines are routed so none overlap or cross a table. Each line is a group "erd-rel:<CHILD>.<fk>><PARENT>" (2 attached end connectors + 1 path). If you move a table, re-run the routing.

PRIORITY (body tint, from the scope sheet): green = Must Have · yellow = Could Have · red = Won't Have · white = not in the sheet.
Red row inside a green table = a Won't field (barcode, batch track, shelf life, parent asset) or an FK to a Won't table.

Sections = domain: FOUNDATION (top) · MAINTENANCE · PRODUCTION (bottom).
Header colour = domain · module:
blue SIT · green SHF/FYR · orange AST · purple REF · yellow PRO
light-green WMS · teal KPI · violet DSR · black AUD
red PRODUCTION · grey MAINTENANCE

Logical model: key + business columns only. created_at / updated_at / deleted_at are not specified in the docs (AUDIT_LOG covers history).
Open items: asset.owner_org_unit_id target; asset_state_log row-id name; kpi_result.waterfall type; stop-threshold storage table (K-6/K-8, engineering); operation_parameter live-tag link; PLATFORM entities TBD.
Old physical ERD kept on page "nge-ERD".
```
