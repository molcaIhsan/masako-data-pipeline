## How to read this document

- **One `####` heading per PRD-003 user story**, in the same order as PRD-003 §5/§6, followed by that story's task table.
- **Task ID** — `T-<STORY-ID>-<nn>`, e.g. `T-US-FND-SIT-001-01`. Paste into ClickUp as a Task under the matching Story card (`US-FND-SIT-001` etc.).
- **Type** — `schema` (entity/migration/DB), `api` (endpoint/service logic), `ui` (screen/component, one per distinct state — default/empty/loading/error/offline/no-permission/success — not collapsed into one task), `validation` (business rule enforcement), `abac` (access-control wiring), `event` (analytics/instrumentation), `test` (one per acceptance criterion), `docs` (an open question or entity-modelling prerequisite that blocks part of the story — not a guess).
- **Depends on** — other Task IDs (or, where a task depends on an entire other *story* rather than one specific task, that story's ID) that must land first.
- **Size** — `S` (well under a day), `M` (about a day), `L` (more than a day, rare by design — the brief was maximum granularity, so almost everything is `S`; `M` is used mainly for the "model this module's entities first" prerequisite tasks on the four concept-only modules).
- **A story marked `CLOSED`/`BLOCKED`/`RENAMED` in PRD-003 gets no task table** (or, when the PRD says it was written out in full for exactly this purpose, a full table prefixed with a BLOCKED warning) — tasks are never invented against a story the PRD itself says not to build.
- **A story with an open `TBD`/question inside it** gets a `docs` task naming exactly what needs deciding and by whom, rather than a guessed implementation.
