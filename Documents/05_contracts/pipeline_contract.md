# Pipeline contract — what Flink and Airflow MUST do (2026-10-02)

> **Audience:** whoever builds the Flink job and the Airflow DAGs in this repo. It's a checklist so nothing is forgotten.
> **Related:** [[app_contract]] (the app side) · [[silver_model]] · [[gold_model]] · [[editing_model]] · [[flink_rules]] · [[airflow_rules]] · [[data pipeline]].
> **Stack:** Java Flink 2.3.0 · Airflow 3.3.2 (no dbt) · one TimescaleDB database, schemas `silver` and `gold`.

## 0. Ground rules for both

| # | Rule |
|---|---|
| R1 | **Flink writes only** `silver.production_events`, `silver.reject_events`, `silver.downtime_events` (+ the Kafka DLQ topic) |
| R2 | **Airflow writes only** the `gold` report tables and `gold.etl_watermarks` |
| R3 | **Neither ever writes** master data, edit / entry tables (`*.downtime_edit`, `silver.downtime_entry`, `*.quality_entry`), approval tables, or `silver.audit_log` |
| R4 | **Idempotent.** A rerun or replay gives the same result: Flink upserts on natural keys; Airflow does delete + insert per shift in one transaction |
| R5 | **Every master-data lookup is as-of:** event time for placement, product codes and tags; `business_date` for binding, cycle time, conversion, routing, flow |
| R6 | **Time.** Store UTC. Day = `shift_instance.business_date` (07:00 → 07:00 local). Never hard-code shift hours or `Asia/Jakarta`. Read `silver.shift_instance` / `site.timezone` |
| R7 | **NULL means unknown, never 0.** Never average rates |
| R8 | **Connect with a distinct `application_name`:** `flink-silver` / `airflow-gold` |

## 1. Flink job (Kafka → silver)

### 1.1 Input
- Topic `machine_metrics` (Telegraf JSON), for example:
  `{"name":"machine_metrics","tags":{"equipment_code":"ANRITSU57-1","line_code":"FI2-L1","source_tag":"PLC/FI2-L1/ANRITSU57-1/ng_count"},"fields":{"payload":"PLC/FI2-L1/ANRITSU57-1/ng_count=206"},"timestamp":"2026-09-30T03:05:55Z"}`
- `event_time` = `timestamp` (UTC). Value = the text after the **last** `=` in `fields.payload`. `equipment_code` / `line_code` are for diagnostics only.

### 1.2 Must do

| # | Obligation |
|---|---|
| F1 | **Event time.** Watermark with 1 min bounded out-of-orderness, plus source idleness so one silent partition doesn't stop the clock |
| F2 | **Master data as broadcast state**, reloaded from `silver` every **1 min** (JDBC): `asset_tags`, `asset_placement`, `asset`, `work_unit`, `work_center`, `area`, `site`, `shift_instance`, `work_unit_kpi_binding`, `asset_product_codes`, `downtime_reason`, `reject_reason`, `product` |
| F3 | **Resolve each reading:** `source_tag` = `asset_tags.node` (valid at event time) → `tag_id`, `asset_id`, `tag_role`, `kind`, `uom_id`. Work unit = `asset_tags.work_unit_id`, else the `asset_placement` valid at event time. Shift = the `shift_instance` of that site with `start ≤ t < end` → `shift_instance_id`, `business_date` |
| F4 | **Counter delta** (keyed by tag, event-time ordered): `delta_counter` → value as-is. `cumulative_counter` → value − previous; first reading = 0 (baseline); value < previous = **reset** → delta = value, `is_reset = true`. Never negative |
| F5 | **Route:** role `total` / `good` → `silver.production_events`; role `reject` → `silver.reject_events` (with `reject_reason_id` from the tag). Upsert on `(tag_id, event_time)` |
| F6 | **Product on each count:** keep the asset's last `product_code` value (a new code counts only after holding **30 s**). Map `raw_value` → `product_id` through `asset_product_codes` valid at event time (exact string match). Unmapped → `product_id` NULL |
| F7 | **Stall detection** on every tag bound to `availability.downtime_reason` with `transform = stall_bucket` (keyed by work unit). Gap between real increments (no increase = same value, delta 0, or no message): **< 60 s nothing · 60–300 s `small_stop` · > 300 s downtime**. Thresholds are **fixed in code** |
| F8 | **Live stop:** event-time timer at last increment + 60 s → upsert an open row (`end_at` NULL, `small_stop`). At + 300 s → promote. On the next increment → close (`end_at`). The `duration` column is generated by the database (never written) |
| F9 | **Category when promoted:** `planned` if the primary reason's `downtime_category` is planned, otherwise `unplanned`. A small stop stays `small_stop` |
| F10 | **Reasons:** every `downtime_reason` tag (primary and secondary assets of the work unit) that turned on or incremented inside the stop window, **ordered by when it turned on** → `downtime_reason_ids` (element 1 = primary = `downtime_reason_id`). None → `'{}'` (unlabelled = unplanned) |
| F11 | **Shift boundary:** at `shift_instance.end_datetime` close the piece at the boundary and open the next piece in the next shift with the **same `stop_group_id`** (no stop crosses a shift) |
| F12 | **`source_event_id`** = deterministic `wu{work_unit_id}-t{tag_id}-{start_at epoch ms}`, unique per piece. Upsert key of `silver.downtime_events`. A replay gives the same ids |
| F13 | **`product_id` of a stop** = the product running when the stop **started** |
| F14 | **Dead-letter topic** with a `reason` for: parse error, unknown `source_tag`, asset not placed, no `shift_instance`, late > 1 min. **Never drop silently** |
| F15 | **Checkpoints:** RocksDB incremental, about every 1 min, exactly-once state; the sink is at-least-once + idempotent upsert |
| F16 | **Never** read or apply edit tables. People's edits are applied by the views, not by Flink |

### 1.3 Not Flink's job
- Unit conversion, cycle times, KPIs: these happen in the views.
- Analog values (speed, activity) are not stored in v1.
- `asset_state_log` is not written.

## 2. Airflow (silver views → gold)

Every gold shift load is the same pattern (`04_gold/test_load_gold.sql`): **one transaction per shift**, skipping frozen work units:

```sql
-- frozen = gold.report_approval WHERE shift_instance_id = :shift AND status = 'approved'
DELETE FROM gold.<table> WHERE shift_instance_id = :shift AND work_unit_id NOT IN (frozen);
INSERT INTO gold.<table> SELECT * FROM silver.v_<view> WHERE shift_instance_id = :shift AND work_unit_id NOT IN (frozen);
-- work_center_shift_report: always recomputed for the shift
-- then upsert gold.etl_watermarks
```

| Gold table | Source view |
|---|---|
| `work_unit_shift_report` | `v_wu_shift_report` |
| `work_center_shift_report` | `v_wc_shift_report` |
| `product_count` | `v_product_count` |
| `reject_count` | `v_reject_count` |
| `downtime_report` | `v_downtime_report` |
| `loss_by_reason` | `v_loss_by_reason` |
| `product_perf_hourly` | `v_product_perf_hourly` |

### 2.1 DAGs that must exist

| DAG | Schedule | Must do |
|---|---|---|
| **A. `gold_shift_close`** | Every 15 min | Find `shift_instance` rows with `end_datetime <= now() − 5 min` (1 min watermark + rollup refresh) that are not loaded yet (no gold row for that shift, or `computed_at` < shift end). Load each shift as above. Then trigger D for those dates |
| **B. `gold_rerun_window`** | Hourly | Reload **every shift that ended in the last 72 h** (the 48 h shopfloor edit window + late data + DLQ replays). Silver edits made after the first load reach gold this way |
| **C. `gold_apply_edits`** | Every 5 min | Find affected `(shift_instance_id, work_unit_id)` from rows **created or voided since the last run** in `gold.downtime_edit`, `gold.quality_entry`, `silver.downtime_edit`, `silver.downtime_entry`, `silver.quality_entry`, and **reopen events** in `gold.report_approval_event` (to_status = `open`). Reload those shifts (frozen ones are skipped automatically), then D for their dates. Keep its own watermark (`etl_watermarks` row per edit table, e.g. `edits:gold.downtime_edit` = max of `created_at` / `voided_at` processed) |
| **D. `gold_rollups`** *(to build)* | Triggered by A / B / C, and daily | **Day** = Σ of the day's shift rows (`business_date`) once all its shifts are loaded. **Month** (`business_date` = 1st) and **year** (Jan 1) are progressive, upserted as they fill. Sum durations and counts; **recompute** rates from sums; MTTR / MTBF via `silver.fn_reliability` over the period window (never averaged); work center the same over its own rows; `product_count_day` = Σ `product_count`. Skip nothing for approval (approval is per shift) |
| **E. `gold_backfill`** | Manual (params: date range, work units) | For back-dated master changes (cycle time, product code mapping, binding, flow, conversion): reload those shifts, then D. **Approved shifts stay frozen**; a reopen is needed first (never a force flag that bypasses approval) |
| **F. `gold_quality_checks`** | After A / D, daily | `SQLCheckOperator`, failing on errors (list in §2.3) |

### 2.2 Must never

- Never write `silver.*` (facts, edits, master), approval tables or `audit_log`.
- Never rewrite a work unit row whose `(work_unit_id, shift_instance_id)` is approved.
- Never use `UPDATE … SET x = x + …`: always rebuild from the views (stateless with respect to edits).
- Never put heavy queries or DB calls at DAG top level. Use `{{ data_interval_start }}` / params, not `now()`, for reproducible reruns ([[airflow_rules]]).

### 2.3 Quality checks (F)

| Check | Severity |
|---|---|
| Day `runtime` and `availability_time` = Σ of its shifts (and month = Σ days, year = Σ months) | error |
| `product_perf_hourly`: Σ runtime per work unit per hour ≤ 3,600,000 ms | error |
| `product_perf_hourly` Σ total_out per shift and product = `product_count.total_out` | report the gap |
| No approved work unit row has `computed_at` later than its approval | error |
| Shifts that ended more than 1 h ago with no gold rows | error |
| Every `work_unit_shift_report` row: `data_status` distribution; `no_binding` / `no_cycle_time` counts per site | warn (configuration gaps) |
| DLQ message rate by reason | warn |

## 3. Facts that make this work (don't break them)

- **Gold can be rebuilt at any time** from Silver: the views read the 1-minute rollups (kept forever) and `downtime_events` (kept forever). The 1-month retention on raw events doesn't block rebuilds.
- **Precedence of edits:** gold edit > silver edit > machine value, latest live edit per field. It is all in `silver.v_downtime_effective` / `v_quality_entry_effective`.
- **Approval** is per work unit × shift. The work center row is always recomputed.
- **Timescale owns rollup refresh, compression and retention** (policies in `ddl_silver.sql`). Airflow doesn't run them, but it must wait for the 1-minute rollup refresh (≥ 2 min after shift end, covered by the 5 min lag in A).
